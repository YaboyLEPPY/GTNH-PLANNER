# Validation and performance handoff

## Verified results

**17 unit tests passed**: quantities 1/20/21, batches, repeated inputs, surplus, stock, cycles, voltage/machine eligibility through MAX, catalysts, alternatives, fluid units, chance-only outputs, the actual 20-circuit source fixture, ledger reservations/target overlap, completion, backup validation/migration, geometry, source prerequisite logic and formatting.

**7 production-browser tests passed**: authentic Ender IO navigation and all 47 chapter entries, actual task/reward panels, persistent quest progress, circuit recipe changes and CSV export, shared-stock completion/undo, malformed-backup rejection and reload, base drag/move/resize/duplicate/connect/delete/undo/redo/floors, real touchscreen grid tap and coordinate/keyboard alternatives, narrow viewport overflow, lazy compression, accessibility and cached offline content.

**Data verification passed**: 3,810 unique quests, 46 source chapters, 3,942 original placements + 67 generated nodes, 4,317 chapter edges / 5,450 internal prerequisites. Every catalogue icon exists. Coordinates and prerequisite lists match source. Three dangling prerequisites and 864 unresolved identity combinations remain explicitly reported. Full source tasks, rewards and unsupported properties are retained. No invented source recipes/items were added.

**Production build passed**: TypeScript + Vite. Core JS is approximately 229 kB / 72.4 kB gzip; planner sections are separate lazy chunks. The entire recipe database is not in the JavaScript bundle.

**Axe found zero violations** across all five default destinations, an LV quest detail and the calculated circuit bill. This is not proof of perfect accessibility for every quest/device. A separate agent performed the independent journey/design review; see DESIGN-REVIEW.md. Physical human gameplay testing remains future work.

**Offline validation passed** for the cached shell and previously loaded quest search after disabling network. Unvisited data still needs the local server. The actual development server was started on port 5173; real requests validated the HTML and decompressed source index.

Frozen `npm ci`, pinned Pillow 11.3 in a virtual environment, and the complete importer were exercised, including regeneration from cached pinned archives. Install and startup instructions were saved to the cloud configuration draft. Fresh-task snapshot restoration and publication have not been tested; no public deployment was performed.

## Measured performance

Method: headless system Chromium, production Vite preview over local loopback; cold fresh browser context, warm reload after service-worker activation. Times include Playwright readiness polling, and parallel checks compete for this cloud machine. This is not a remote connection or physical-device benchmark. Page Resource Timing excludes document HTML, service-worker background precache and icons loaded later below the fold.

| Check                                                  |         Observed |
| ------------------------------------------------------ | ---------------: |
| Cold first usable chapter menu                         |           396 ms |
| Cold page-resource transfer by readiness gate          |     85,379 bytes |
| Warm first usable menu                                 |           550 ms |
| Warm page-resource transfer                            | 0 bytes (cached) |
| Subsequent full-book search                            |            76 ms |
| Recursive 20-circuit ingot-boundary bill               |          1356 ms |
| LV graph animation-frame mean / maximum while dragging | 16.67 / 16.70 ms |

The graph sample contains 39 intervals for a fitted 159-node LV chapter, measured separately without parallel browser suites. It measures frame intervals, not input latency. Reproduce with `node scripts/measure_graph.mjs` against a running production preview on port 4174, or pass another local preview origin. Raw reports: `docs/readiness-metrics.json`, `docs/graph-metrics.json`. Browser readiness measurements are generated by `tests/browser/readiness.spec.ts`.

Catalogue gzip: 1,495,782 bytes versus 11,856,948 uncompressed. Search gzip: 1,443,745 versus 12,027,120. Initial index: about 7.3 kB compressed. Request assertions verify catalogue/search are absent from initial loading; recipes load per product. These are measured size reductions, not a before/after timing claim against the unavailable prior prototype. The cold usability test uses a 5-second sanity budget; hardware/connection results will vary.
